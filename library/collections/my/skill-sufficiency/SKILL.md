# Проверка достаточности навыков

Обязательный управляющий навык для Product Manager v.1. Выполнять до выбора предметных навыков, при изменении задачи и перед итоговым ответом. Работать в рамках запроса пользователя и правил среды.

## До выполнения

1. Разложить запрос на все ожидаемые результаты и ограничения. Для каждого записать, что означает полный ответ или готовый артефакт. Учитывать исходную цель и последующие уточнения.
2. Составить короткую матрицу: результат → нужная компетенция → выбранный навык → необходимые данные/инструменты → критерий приёмки → пробел.
3. Прочитать выбранные SKILL.md. Совпадение названия/описания с темой не доказывает достаточность: проверить глубину, предметную область, применимость и ограничения. Несколько навыков допустимо объединять при ясной передаче результатов.
4. Различить причины пробела:
   - SKILL: недостаточно компетенций или глубины методики;
   - DATA: нет исходных данных, требований, первоисточника или актуальной версии;
   - TOOL: нет инструмента, доступа или технической возможности;
   - AUTHORITY: требуется решение уполномоченного лица или предметная экспертиза;
   - SCOPE: неясны существенные границы результата.
5. Для SKILL искать дополнение через библиотекаря и library/INDEX.md; прочитать кандидат, проверить лицензию и зависимости. Добавление навыка не устраняет DATA/TOOL/AUTHORITY автоматически. Нельзя заменять отсутствующие доказательства уверенной формулировкой.
6. Продолжить независимую часть работы. Уточнять только существенные недостающие сведения; не просить заново уже принятое решение. Новый узкий навык можно использовать в разрешённом объёме, записав причину и результат. Постоянное расширение реестра фиксировать в истории профиля.

## Перед ответом или сдачей

Сверить каждый исходный результат с реально созданным и проверенным выходом. Проверить содержательную полноту, источники, ограничения, ссылки и сохранение. Отдельно проверить, что предложения не выданы за решения, а фактические проверки — за выполненные без доказательств.

Для каждой строки матрицы установить: covered, partial или blocked. Частично выполненная задача не становится complete только потому, что все выбранные навыки прочитаны.

Итоговая оценка:
- sufficient — результаты покрыты навыками и необходимыми средствами; финальное complete допустимо только после проверки реального выхода;
- needs-skill — указать точный пробел и дополнительный навык/метод;
- needs-input — указать данные/доступ/решение, без которых зависимая часть не готова.

Если пробел остался, кратко назвать выполненную часть, конкретное ограничение и следующий шаг. Не обещать абсолютную полноту и не использовать выдуманный процент уверенности.

## Запись в проекте

В задаче хранить: ожидаемые результаты, активированные навыки, причины дополнения, покрытие, проверки и оставшиеся пробелы. Полная таблица в ответе нужна только когда помогает пользователю; для простой задачи достаточно краткой проверки.

## Примеры различения

- PRD и план запуска: проверить, покрыты ли требования, экономика, операции, критерии запуска; один навык оформления PRD может быть недостаточен.
- Соответствие ГОСТ: даже при наличии навыка качества без текста, редакции и применимости есть DATA, а не только SKILL.
- Сохранение на Drive: навык документации без подключённого доступа оставляет TOOL; нельзя объявить файл сохранённым.
- Утверждение гейта: подготовка пакета не заменяет AUTHORITY принимающего решение.
