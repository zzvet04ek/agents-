# Выбор навыков и проверки библиотеки

## Избранное

`favorites.yaml` по-прежнему принимает `коллекция/имя`. `index` создаёт небольшие
адаптеры в `.agents/skills/` и `.claude/skills/`: например,
`marketing-copywriting` и `claude-skills-copywriting`. Уникальное имя записывается
и в папку, и в поле `name` файла `SKILL.md`.

Адаптер читает исходный файл в `collections/`, поэтому скрипты, ресурсы и
относительные ссылки остаются в исходном контексте. Старые копии с маркером
`.library-favorite` мигрируют автоматически. Ручные навыки сохраняются.
Неизвестный или неоднозначный ID — ошибка до удаления установленных адаптеров.
Конфликты проверяются в обеих средах заранее; при ошибке записи изменения
установленных адаптеров откатываются в обеих средах.

## Правила выбора

`routing.yaml` задаёт основной навык и допустимые альтернативы для задачи.
Это небольшая политика поверх полного архива: исходные навыки не удаляются.

```bash
python3 library/tools/library.py route "Напиши текст для лендинга"
python3 library/tools/library.py route "Найди статьи через Exa" --available exa-api
python3 library/tools/library.py route "Используй academic/deep-research" --commercial
```

Порядок:

1. Явные квалифицированные ID пользователя имеют приоритет; они не подменяются.
2. Для обычного запроса сопоставляются регулярные выражения `match`; учитывается
   `priority`, затем суммарная длина совпадений. Равные лучшие правила с разными
   основными навыками дают `ambiguous`.
3. Альтернатива с совпавшим `when` проверяется перед основным навыком. Остальные
   условные альтернативы не выбираются. Безусловные альтернативы — запасные варианты.
4. `requires` проверяется по явно переданному списку доступных возможностей.
   Список не проверяет установку или авторизацию API: передавать можно только
   фактически доступные в текущей сессии инструменты. Без `--available`
   доступность неизвестна; `--available ""` означает пустой список.
5. При `--commercial` навыки с NC не выбираются. Явный запрещённый ID даёт
   `blocked`, а не автоматическую замену.
6. `no_route` означает обычный поиск по индексу. `blocked` и `ambiguous`
   требуют объяснения недостающей возможности или разрешения неоднозначности.

Код возврата `route` — 0 при выборе, 1 в остальных случаях. Поле `path` указывает
исходный `SKILL.md`. Сначала читается один основной навык; специалисты добавляются
для конкретных недостающих возможностей. Выбор инструкции не означает выполнения
научного процесса и не подтверждает готовность всех её программных зависимостей.

## Реестр агентных инструкций

`index` собирает `AGENTS_INDEX.md` и `agents.index.json` из Markdown-файлов во всех
вложенных каталогах `agents/`. Файлы с одинаковым SHA-256 представлены одной
логической записью со всеми исходными путями. Разные тексты с одинаковым названием
остаются разными записями. Стабильный ID определяется содержимым.

JSON хранит хеш, объявленные инструменты, исходные лицензии, навыки-владельцы и
прямые ссылки. Непрямые и динамически формируемые зависимости не устанавливаются
этим статическим анализом. Реестр не устанавливает и не запускает агентов.

## Локальные проверки и CI

```bash
python3 -m unittest discover -s library/tools/tests -v
python3 library/tools/library.py check --generated
python3 library/tools/library.py eval-routes
```

`check` обнаруживает повторные ID, неописанные в политике совпадения имён,
неизвестные маршруты и связанные навыки, ошибки категорий, изменения лицензий,
отсутствие закреплённых коммитов и расхождение сгенерированных файлов.
Идентичные навыки и новые навыки без русского описания или лицензионного эталона
выдаются предупреждениями для просмотра; они не удаляются автоматически.

После осмысленной проверки изменения лицензий обновляется эталон:

```bash
python3 library/tools/library.py baseline
```

Не запускайте `baseline` автоматически после обновления источников: так можно
скрыть изменение условий. Проверяйте diff `audit-baseline.json` при ревью.

Workflow `Library checks` выполняет офлайн-проверки на Python 3.10 и 3.12.
Еженедельная синхронизация прикладывает диагностический JSON к запуску Actions
и отмечает её результат в PR. Ошибка диагностики не скрывает обновление: PR
можно просмотреть, а обязательность проверок при слиянии задаётся настройками GitHub.
Ни один из этих workflow не вызывает модели, внешние научные API или устройства.

## Обновление и воспроизводимое восстановление

```bash
# Получить новые версии источников и обновить lock-файл:
python3 library/tools/library.py sync scientific

# Восстановить версии, записанные в существующем lock-файле:
python3 library/tools/library.py restore --locked
python3 library/tools/library.py restore --locked scientific
```

Восстановление получает точные SHA, не текущие вершины веток. Оно не меняет
lock-файл и не затрагивает `collections/my/`. До начала проверяется соответствие
источника, лицензии и настроек копирования сохранённому `config_sha256`.
Если эти настройки изменены намеренно, нужен новый `sync` и просмотр diff.
Для восстановления требуется доступ к исходным репозиториям и сохранённым
коммитам. Если upstream удалил коммит, восстановление завершится ошибкой;
команда не подменяет его новой версией.

## Повторяемость маршрутов и модели — отдельные измерения

`evals/routing.yaml` содержит 30 русских задач с ожидаемыми маршрутами и условиями.
`eval-routes` повторяет каждую три раза, проверяя политику и её стабильность.
Это не результат тестирования LLM.

Для реальных независимых модельных прогонов предусмотрен JSON-адаптер:

```bash
# Сначала проверить одну задачу, затем полный набор:
python3 library/tools/eval_model.py \
  --runner library/tools/codex_route_runner.py \
  --case landing --output /tmp/routing-model-smoke.json
python3 library/tools/eval_model.py \
  --runner library/tools/codex_route_runner.py \
  --output /tmp/routing-model-results.json
```

Каждая задача и повтор запускаются отдельным процессом; ожидаемый ответ не
передаётся модели. Адаптер передаёт только задачу, политику и метаданные навыков,
не выполняет запрошенную пользователем работу. Используется модель, выбранная
в локальной конфигурации Codex; модель не переопределяется скриптом. Для сравнения
результатов нужно фиксировать эту конфигурацию, версию CLI и коммит библиотеки.
Отчёт хранит выбранный ID, статус, правильность, устойчивость по задаче и время
процесса; он не измеряет стоимость токенов или качество выполнения самого навыка.

На первой ошибке исполнителя серия останавливается и помечается неполной.
`evals/model-status.json` фиксирует проверенную доступность: на этапе внедрения
Codex CLI отклонил авторизацию с HTTP 401, поэтому модельные задачи не выполнены.
После повторной авторизации CLI эти команды позволяют завершить проверку.
Результаты запуска через произвольный `--runner` требуют отдельной проверки
личности исполнителя: тестовый JSON-скрипт не является моделью.
